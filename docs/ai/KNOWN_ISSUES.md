## Most important gotchas

The traps most likely to cost a fresh session time:

1. **The harness exit code only reflects page errors.** Console errors, warnings and throwing
   `eval` steps do not fail `npm run check`; read the summary / `report.json`
   ([TOOL-01](#tooling-and-harness)).
2. **Adding to a catalog list breaks the Starfall generator** until the level uses the new entry
   ([LVL-01](#levels-and-generators)).
3. **New defaults change every saved level** on its next save (byte stability) ([LVL-03](#levels-and-generators)).
4. **Weather overwrites live settings every frame** (`grade.temperature`, `grade.saturation`,
   `lighting.settings.*Mul`, wind, god-ray and particle intensities) — tune `weather.tuning` /
   `Game._tunePost` ([GAME-10](#game)).
5. **The ≤ 12-light cap is real and the light count is frozen after load** — never add / remove /
   hide lights at runtime ([LIT-05](#engine--lighting)).
6. **Anything first drawn mid-game hitches** unless compiled at load against `postfx.sceneTarget`
   ([REN-11](#engine--rendering-and-post-processing)).
7. **Scripted editor saves write real files**: the harness' dev server has the level API
   ([TOOL-03](#tooling-and-harness)); a level named "Untitled" saves to `untitled.json` ([LVL-05](#levels-and-generators)).
8. **Headless fps is meaningless** (capped ~57–60); GPU time is noisy on the shared GPU ([ENV-01](#environment)).
9. **`convert-emberfall.mjs` must not be re-run** ([LVL-04](#levels-and-generators)).
10. **An object type missing from `LevelObjectBuilder.build`'s switch silently builds nothing**
    at run time — `npm run typecheck` catches it for a `kind: 'prop'` type
    ([PROP-10](#engine--terrain-water-props-textures)).
11. **Renaming a level re-seeds its terrain noise** — the terrain tint and grass variation change
    ([LVL-10](#levels-and-generators)).
12. **The harness `tab` step does not wait for the play-test tab** — load
    `index.html?level=local:__playtest__&autostart=1` with a `goto` step instead ([TOOL-11](#tooling-and-harness)).
13. **`renderer.info` reads 0 draw calls from scripts in the game** (the debug stats reset it every
    frame) — use `__game.state().drawCalls` ([UI-04](#engine--core-input-ui)).
14. **The level API serves only its own origin** — a page on another port (another localhost
    server included) gets 403, writes need `PUT` with `content-type: application/json` (curl:
    add `-H 'content-type: application/json'`, else 415) ([LEVEL_STORAGE_API §5](../specs/LEVEL_STORAGE_API.md#5-the-dev-server-rest-api-apilevels)).
15. **Combat exists only on levels with enemies** — a peaceful level must create nothing combat-related
    (`game.combat === null`, same fingerprints); the combat catalog types are covered by
    `make-cinderwatch-pass.mjs`, not by Starfall ([COMBAT-01](#combat), [LVL-01](#levels-and-generators)).
16. **Combat tints longer than a few frames use the Sprite3D highlight, and HDR colours sit at the
    bloom threshold** — a `uFlash` mix flattens a sprite; a marker or effect colour above luminance
    1.05 blooms into a haze ([COMBAT-03](#combat), [COMBAT-15](#combat)).
17. **Stepped combat scripts count engine frames, and hit-stop freezes whole sub-steps** — step
    until a state condition (`combat.stepUntil(pred, maxFrames)`), and re-record the golden values
    when you change a number ([COMBAT-04](#resolved-2026-09-28),
    [TASK_PLAYBOOKS §20](TASK_PLAYBOOKS.md#20-tune-combat-balance-feel-look)).
18. **The play-through bot is deterministic only in fixed step** — `combat.play.json` loads the
    level with `&fixedstep=1`; compare its `summary` line / `digest` between runs. Timings read 0
    there, and the real-time variant (`combat.play.realtime.json`) must run alone
    ([COMBAT-14](#resolved-2026-09-28), [TOOL-17](#tooling-and-harness)).
19. **Vite never type-checks** — the dev server and the build succeed with type errors; run
    `npm run typecheck` (0 errors in both programs). It does not see the `eval` strings of the
    action scripts, and with `strict` off an untyped value is `any` and silently unchecked
    ([TC-01](#type-check), [TC-02](#type-check)).

## Engine — rendering and post-processing

| ID | Issue and impact | Status | Suggested direction |
| --- | --- | --- | --- |
| REN-01 | **Resolution-governor steps reallocate the drawing buffer and every PostFX target** — a one-off hitch of a few ms, up to ~0.2 s when other apps load the GPU. Mitigated: decisions on the median of the last 5 GPU samples, down after 4 slow medians (> 13.5 ms), up after 20 fast ones (< 8.5 ms), never twice within 3 s, minimum scale 0.7. | code, report | Render into fixed-size targets and scale the viewport instead of reallocating (the "no-reallocation redesign" left open in review 07). |
| REN-02 | `dofScale` 0.25 aliases: the prefilter reads only a 2 × 2 footprint of each 4 × 4 block. | report | Keep the default 0.5 (or 1). A 4 × 4 prefilter would be needed for 0.25. |
| REN-03 | Near bokeh sprites are drawn on top without occlusion by other near geometry. Not visible in the diorama framing. | report | Depth-test near discs against a near-depth layer if it ever shows. |
| REN-04 | Transparent / additive effects that do not write depth (particles, god rays, glows) take the circle of confusion of the surface behind them — inherent to depth-based DOF. Distant sparkles can read slightly brighter as bokeh at night. | design | Accept; for a hero effect that must stay sharp, give it depth (cutout blending) like leaves / petals. |
| REN-05 | The MSAA depth resolve picks one sample, so the CoC at anti-aliased silhouettes comes from that sample. | report | Accept (invisible at the target resolution). |
| REN-06 | The orthographic-camera CoC path exists only in code; no sandbox exercises it. | report | Add a `postfx.html` variant before relying on orthographic cameras. |
| REN-07 | Residual grid-phase alternation (≈ 4/255 mean over a small window) for one near firefly partly occluded by a bush outline; not visible frame to frame. | report | None needed. |
| REN-08 | Non-finite scene pixels (NaN / Inf) are scrubbed to black so they never smear through blur and bloom — a shader bug can show up as black specks instead of a blown-out frame. | design | When you see black specks, look for NaN in your shader. |
| REN-09 | Sky dome clouds snap to a latitude / longitude grid: a one-column seam toward −X and stretched cells near the zenith; overhead clouds at noon become soft blobs. The sky above the horizon is rarely seen from the gameplay camera. | report | Screen-space or cube-mapped cloud pixels if a low camera ever features the sky. |
| REN-10 | The sky draws after opaque objects with a far-plane depth test (`earlyZ`). An **opaque** material that does not write depth is painted over by the sky. | design | Give such effects `transparent: true` (or `new Sky({ earlyZ: false })`). |
| REN-11 | Shader programs are keyed by render target; anything first drawn mid-game (a material, emitter variant, burst pool, post pass) compiles then and hitches (100–300 ms measured for waterfall bursts before they were primed). Emberfall compiles 57 programs at load and none during play. | code, run | Compile new content at load: add it to the scene before `Game._compileScene()`, prime bursts in `Game.init`, add passes to `PostFX.warmup()` (golden rule 2). |
| REN-12 | The fog "start" patch (`installFogStart`, [`demo/AtmosphereFog.js`](../../src/demo/AtmosphereFog.js)) replaces `THREE.ShaderChunk.fog_vertex` **globally** and only once per page (the first start distance wins). The editor does not install it and uses a scaled fog instead, so distant haze in the editor's game view differs slightly from the game. | code | Keep custom shaders on the standard fog chunks so they follow the patch; if the editor must match exactly, install the same patch there. |
| REN-13 | **The warm-up does not compile shadow-pass programs.** `Game._compileScene()` runs `renderer.compileAsync(scene, camera)`, which builds the main-pass program of every material; the depth programs of the shadow pass (for alpha-tested casters a `depth` program with the map and alpha test) are built by three.js the first time such a caster is drawn into the shadow map — i.e. when one first comes within the sun's shadow frustum. A level whose spawn has no caster of some kind nearby compiles that program during play (REN-11). Measured on Gildhaven on 2026-10-02: 58 programs at load, 59 after the first walk into High Town (the pine foliage's depth program; the woods round its spawn had no pines); worked around in the level with two pines by the King's Road (59 at load and after the 26-view tour, `sandbox/gildhaven.tour.json`). Starfall Vale already has all 59 at load because its spawn's shadow frustum holds every caster kind. | run | Prime the depth programs at load: draw each alpha-tested caster material once into the shadow map (e.g. one far-below proxy mesh per caster material, as the bursts are primed in `Game.init`), then check that the program count at load equals the count after a level tour. |

## Engine — lighting

| ID | Issue and impact | Status | Suggested direction |
| --- | --- | --- | --- |
| LIT-01 | **Lamps beyond the pool stay unlit.** Twelve pooled lights cover 20+ lamps in Starfall's square, so some lamps near the camera have no point light at any moment (their glass still glows). The build measured ≈ 3.4 unlit lamps within 12 units on average; the review then lowered `priorityWeight` 4 → 1.5 so nearby lamps win (a 272-spot sweep afterwards: 5 unlit lamps within 9 units in total, was 114). Hand-overs fade (0.35 s out / in), re-ranked every 0.2 s. | code, report | Fewer lamps in dense spots, or cheap fake light (emissive ground decals / light cards) for lamps without a real light. |
| LIT-03 | Dusk / sunset (≈ 18.0–18.6 h) is moody and fairly dark; in lantern-lit places night is brighter than dusk (Emberfall start spot: dusk 54.8 vs night 62.2 mean luminance) because lanterns reach full strength only at night (`nightFactor` 0.22 at 18.45 → lamps ≈ 34 %). Dusk is no longer a dark trough away from the lanterns. | report | Tune `KEYFRAME_OVERRIDES` ([`demo/config.js`](../../src/demo/config.js)) or a lamp `dayIntensity` curve that rises earlier. |
| LIT-04 | While the clock runs the light direction rotates, so shadows crawl slightly (texel snapping only removes camera-motion shimmer). With `timeSpeed = 0` shadows are fully stable. | design | Accept; freeze the clock for screenshots. |
| LIT-05 | **Point-light count must never change after the first frame** (adding, removing or toggling `light.visible` recompiles every lit shader). The ≤ 12 budget is not enforced by `LightingSystem.addPointLight` (the game enforces it by routing every light through a `LightPool` of `MAX_POINT_LIGHTS` = 12). | code, design | Create all lights at load; fade `handle.intensity` / `fade`; go through `LightPool`. |
| LIT-06 | Point lights never cast shadows. | design | — |
| LIT-07 | Big levels limit the shadow frustum depth to 60 units up-sun / 45 down (`BIG_LEVEL_BATCHING.shadowUp` / `shadowDown`, `setShadowDepthRange`): at the lowest sun, very tall casters far up-sun can lose the far end of their shadows. Small levels are unaffected. | code | Raise `shadowUp` if a tall landmark's shadow is visibly cut. |
| LIT-08 | Very wide / far views (distance ≥ 60, beyond the game's 18–42 range) wash out at golden hour (FogExp2 + sea-of-clouds haze + bloom). | report | Scale `settings.fogMul` / `sky.lowerClouds` with distance if photo mode ever allows it. |
| LIT-09 | Lantern flicker amplitude is ±(0.85 × `flicker`) — about ±25 % at the default 0.3. | design | Lower `flicker` per light for calmer lamps. |
| LIT-10 | Lantern glass does not flicker with its lamp: `World._registerEmissive` registers each emissive material once (shared material) without `flicker` / `light`, although `LightPool` offers `flickerSource()` and `registerEmissive({ light })` links. | code | Link glass materials to their descriptor (per-lamp material or an instanced attribute) if the mismatch shows. |
| LIT-11 | **Static vs pooled mode is decided by the descriptor count.** A level with ≤ 12 light descriptors gets one permanent light each (Emberfall has exactly 12); a 13th descriptor switches the whole level to pooled mode (lights follow the camera, hand-overs fade) — a visible behaviour change. In static mode `LightPool.update` returns early, so a later change of `nightDayIntensity` is ignored (its JSDoc says "live"); `Weather` (and the editor preview, both through `WeatherLook.applyLampDayGlow`) also writes `handle.dayIntensity` directly. | code | Count light descriptors before adding a light to a small level (`__game.world.stats.lightDescriptors`, `__game.world.lightPool.pooled`). The editor preview's pool is created with `fixed: true`, so it always has 12 lights and crossing 12 descriptors there changes no light count. |

| --- | --- | --- | --- |
| SPR-01 | Each sun-facing sprite costs 3 colour-pass draws (quad, a shadow proxy with `colorWrite` off, a blob) plus 1 in the shadow pass on **small** levels (~20 NPCs ≈ 80 draws). | SPR-04 | No half-texel UV inset in `Sprite3D`; frames use the full 32 px height and touch row 0 in bob frames. Under heavy minification NEAREST could sample the neighbouring row (not seen at the diorama zoom). | code, report | Inset frame UVs by half a texel. |
| SPR-05 | The right-facing sheet row is the left row mirrored, so its light comes from the upper right (asymmetric gear is redrawn correctly). | design | — |
| SPR-06 | `SpriteManager.update` iterates the live array: removing a sprite from inside a sprite callback (`onAnimationEnd`, `onFrameChange`) during update can skip one other sprite that frame. | code | Iterate a copy or defer removals. |
| SPR-07 | Lit particles (leaves, smoke) are tinted by the sun plus a fixed ambient only — point lights do not light them, so leaves near lanterns stay dark at night. | report | Add a cheap nearest-lights term if it matters. |
| SPR-08 | Particles have no soft-particle depth fade (smoke and mist cut the ground with hard edges), no terrain collision (rain and leaves pass through), and normal-blended particles in one emitter are not depth-sorted. | report | Soft particles need the scene depth in the scene pass (not available today). |
| SPR-09 | Stateless GPU motion multiplies by `uTime` in float32: after many hours of uptime rain and dust positions quantise and jitter (cosmetic). | report | Wrap `uTime` per emitter period. |
| SPR-10 | Fireflies' hot cores tone-map to pale yellow-white; the green-gold hue lives in the halo and the bloom. | report | Accept or lower `hdr`. |

| SPR-13 | `Sprite3D.play()` warns about an unknown animation name only once per sprite (one `_warned` flag), so a second, different unknown name on the same sprite is never reported. | code | Keep a set of warned names. |

## Engine — terrain, water, props, textures

| ID | Issue and impact | Status | Suggested direction |
| --- | --- | --- | --- |
| TER-01 | **One-level ledges are walkable.** `TileMap.move` uses `maxStep = 0.55` > `LEVEL_HEIGHT` 0.5, so a 1-level step can be climbed, including onto a stair tile from its side. Cliffs need ≥ 2 levels to block. | code, design | Level design rule: blocking cliffs ≥ 2 levels (or block tiles). |
| TER-02 | `move()` escape mode: a character starting inside a wall (e.g. teleported next to a cliff) can keep moving until its centre reaches the wall edge — never climbing, but the sprite may half-clip. `Game.teleport` snaps to a standable spot, which avoids it. | report | Use `Game.teleport` / `_standable`, not raw position writes. |
| TER-03 | `move()` tests the centre plus 8 perimeter points, so a tile corner can intrude up to ~2 % of the radius. | report | Accept. |
| TER-04 | With `Water` option `level`, `TileMap.getWaterSurface()` / `tile.waterSurface` still report `map.waterLevel`; only the mesh uses the override. | report | Use per-tile legend `waterLevel` / `waterDepth` instead of the option. |
| TER-05 | Night water is a fairly bright saturated blue and sunlit golden-hour water leans slate / mauve (plausible orange-horizon reflection). `Weather` dims water brightness to 0.66 and glints to 0.55 at night. No geometric reflections (sky / fog fresnel only). | report, code | Tune `brightness` / `water.glint`; reflections are out of scope. |
| TER-06 | The shore texture (8 texels per tile) is re-checked only when the TileMap's collider **count** changes (`Water.update`), and then re-baked if the signature of the static colliders standing in water changed; `dynamic` colliders (walking villagers) are excluded. A collider moved in place is not detected: after moving a static collider in water call `water.refresh()` (and `tileMap.collidersChanged()` so the collider grid re-indexes). | code | Mark moving colliders `dynamic: true`. |
| TER-07 | Terrain geometry, AO and tint are baked; the game builds once. Grass fringes only appear between tiles at the same height and only from grass; other pairs keep straight borders. Brims extend over convex corners only on N / S faces. | report | Extend fringe rules if new ground types need soft borders. |
| TER-08 | Stairs are one level per tile with 4 steps of 2 px risers — they read thin from afar; busy tread textures (stone tiles) look noisy. | report | Prefer cobblestone / wood-deck treads. |
| TER-09 | The organic UV-variation shader costs ~1.2 ms at 1600 × 900 (terrain ≈ 2.7 ms incl. the shadow pass). | report | Cache the per-texel variation in a small data texture if the frame gets tight. |
| TER-10 | Waterfalls face only N / S / E / W (axis-aligned); the engine's waterfall creates no particles itself — it returns a `mist` emitter descriptor, and the game adds the spray bursts (`Game._waterfallFx`, `splash` / `sparkle`). | code | — |
| TER-11 | `TileMap.rebuildChunkSteps` removes only meshes whose `userData.chunk` matches; after `consolidateChunks` a merged batch covering that chunk is not dissolved, so the old batch and the new chunk meshes would both draw. `rebuildChunks` handles the case; no current caller mixes them. | code | Dissolve the covering batch first if you combine the two. |
| TER-12 | Water defaults differ by layer: the `Water` class defaults to `reflect` 0.1 / `neutral` 0.35 / `flow` [0, 0.3], the level defaults (`DEFAULT_WATER`, `buildLevelTerrain`) are 0.2 / 0.2 / [0, 0.45]; `waterLevel` is 0.4 in `createEmptyLevel` but 0.35 when `normalizeLevel` or `TileMap` fill a missing value (LVL-06). | code | Only matters for engine users who build `Water` directly or hand-written files without the keys. |
| PROP-01 | Unmerged houses cost 10–13 draw calls each (every texture is its own material) — a village without `PropFactory.mergeStatic` would exceed the 300-call budget. | report | Always merge static props (the game and editor do). Texture atlasing was declined (large refactor). |
| PROP-02 | Diagonal bridges: `walkRects` and rail colliders are AABBs of rotated pieces and over-cover the water beside the deck; axis-aligned bridges are exact. | report | Use axis-aligned bridges, or oriented walk surfaces. |
| PROP-03 | **Bridge ends one level above the bank are not enterable**: the first arched plank sits `0.5 + arch · sin(π / 2n)` above a bank one level down (0.558 at one Starfall bridge) — just over the 0.55 step. Level › *Check for problems* lists such ends (`bridgeStepIssues`). | code | Level the bank, set `deckY`, or reduce `arch`. |
| PROP-04 | Tree canopy cards (and sprites) are tuned for the ~32° gameplay pitch; from steep editor angles they look flatter. | report | — |
| PROP-05 | Houses clamp `stories` to 1–2; story heights other than the defaults (3 / 2) can misalign the `timber_frame` beam pattern. | report | Keep default story heights with timber walls. |
| PROP-06 | Wall-torch glow cards can meet the wall along a faint vertical line when seen > ~30° off the wall normal (≈ 5 % glow). | report | A soft-particle fade would need scene depth. |
| PROP-07 | Prop-factory default interact ids repeat (`house`, `stall`…) when `opts.id` is not passed. `LevelObjectBuilder` always passes the level object id. | code | Pass `opts.id` when calling `PropFactory` directly. |
| PROP-08 | `cliff`, `grass_side` and `dirt_side` are 1 × 1-unit textures (contract size), so long cliff faces repeat every unit horizontally (softened, not removed). | report | A contract addition for 4 × 1-unit side textures (TileMap already reads `meta.units`). |
| PROP-09 | Alpha textures (leaves, pine, fence, flower box) are uploaded from a 2D canvas, losing colour under transparent texels: edges darken at mip ≥ 1 (invisible at the HD-2D zoom, where mip 0 is used). `grass_side`'s lip uses the grass ramp and looks brighter than `grass_dark` tops. `normalScale` was tuned under sandbox lighting. Sign boards carry pseudo-lettering; door / window / lantern decals ignore the seed. | report | Upload ImageData with bled colour if foliage is ever minified; override `normalScale` per material. |
| PROP-10 | **An object type that `LevelObjectBuilder.build` has no `case` for returns `null`** — a new `kind: 'prop'` catalog entry builds nothing, silently, in the game and the editor preview. Since 2026-09-30 the **type check** catches it: the default branch returns `null` through a cast to `NullForNonProp<typeof obj.type>` ([`level/types.d.ts`](../../src/engine/level/types.d.ts)), which fails for a prop type that reaches it; the assertions at the end of [`world/types.d.ts`](../../src/engine/world/types.d.ts) fail for a prop type without a `PropFactory` method of its name and for a catalog `defaults.opts` key that the method's typed options do not declare (`house`, `marketStall`, `bridge`, `rock`, `tree`). Run time is unchanged. | code | Add the case (TASK_PLAYBOOKS recipe 1) and run `npm run typecheck`; a warning in the default branch would also catch it at run time. |
| PROP-11 | `parseColor` in [`pixel/PixelCanvas.js`](../../src/engine/pixel/PixelCanvas.js) accepts `#hex` strings, arrays and `{ r, g, b }` objects only: a numeric colour (`0xRRGGBB`) throws `TypeError: c.trim is not a function`, and CSS colour names parse silently to garbage (`'red'` → opaque black). `CharacterSprites` normalises its colours itself; direct `PixelCanvas` / `PropSprites` callers are unprotected. | code | Pass `#rrggbb` strings (or palette entries); accept numbers in `parseColor` if needed. |
